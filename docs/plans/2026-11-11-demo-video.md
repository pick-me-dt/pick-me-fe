# 시연영상 촬영 대본 (2026-11-11 작성, 11/14 촬영)

시연영상은 계획서 7.4 콘티(`../docs/2026-11-10-pickme-vehicle-app-plan.md` 7장)를 따릅니다. 이 문서는 그 콘티를 지금 앱과 서버에 맞춰 장면별 조작으로 바꾼 것입니다.
조작은 모두 터미널(`scripts/demo.sh`)·매장 대시보드·Virtual Console로 합니다. 앱 화면에는 시연 컨트롤이 보이지 않습니다(`panel off`).

## 1. 무엇이 실제이고 무엇이 모의·가짜인가

촬영 전에 이 표로 자막의 [실제]·[모의]·[목업] 표기를 정합니다.

### 1.1 실서버로 찍을 때 (권장)

콘티 장면은 모두 2차 서버로 동작합니다 ([2차 서버 테스트](2026-11-11-server-e2e-v2.md) 2장).

| 구분 | 내용 |
| --- | --- |
| **실제** | 예약 → 매장 수락 → 제조 시작 → 준비 완료 → 수령의 주문 상태 (픽미 서버) |
| **실제** | 제조 시작 추천·예상 수령·지연 시간 계산 (서버 `pickup-timing.ts`) |
| **실제** | 주문번호 P-021 (서버 초기화 때 맞춤), 대시보드 ↔ 차량 실시간 반영 |
| **실제** | 기어 P/D (Car API. 입력은 Virtual Console), 주행 중 화면 제한 |
| **모의** | 남은 시간(ETA) 전부. `eta 6`·`delay 4`로 넣은 값이 실제 시간만큼 줄어듭니다. 에뮬레이터 위치가 움직이지 않아 실측할 수 없습니다(게이트 G3) |
| **모의** | 정체(도착 지연). 터미널 `delay` 명령으로 넣습니다 |
| **서버 목업** | 결제. 예약 때 승인, 수령 때 확정하는 목업이며 실제 결제는 없습니다 (`pick-me-be/README.md` 102줄) |
| **서버 목업** | 매장 POS·DT 연동. 목업 DT 어댑터가 받습니다(외부 주문번호 `MOCK-…`) |
| **서버에 없음** | 가격 변경(V02-PC), 매장 목록의 도착 예상 시간, 메뉴 옵션(Regular), 브랜드 이름. 콘티에는 나오지 않습니다 |

### 1.2 가짜 서버로 찍을 때 (대안)

앱 안의 가짜 서버(`data/fake/FakeServer.kt`)가 서버와 매장 역할을 모두 합니다.

| 구분 | 내용 |
| --- | --- |
| **가짜** | 주문 상태와 매장 조작 전부. 터미널 `accept`·`prepare`·`ready`·`pickup`이 직원 역할을 합니다. 매장 대시보드는 영상에 나오지 않습니다 |
| **가짜** | 제조 타이밍 계산. 서버와 같은 식이고 준비 3분·입구 이후 2분입니다 (`FakeServer.kt` 기본값) |
| **가짜** | 주문번호 P-021부터 차례로 붙입니다 |
| **가짜** | 품절·가격 변경·접수 종료 (`sold-out`·`price-up`·`closed`) |
| **가짜** | 매장 목록(양재 6분·서초 9분), 메뉴 옵션 Regular, 브랜드 「픽미 커피」. 모두 Figma 예시 값입니다 (`SampleData.kt`) |
| **실제** | 기어 P/D(Car API) |
| **모의** | ETA (1.1과 같음) |

## 2. 촬영 준비

1. 백엔드를 켭니다 (`pick-me-be` 폴더).

```bash
docker compose up --build -d --wait
```

2. 앱을 실서버 주소로 설치합니다.

```bash
./gradlew :app:installDebug -Ppickme.serverUrl=http://10.0.2.2:3000
```

3. 시연 컨트롤을 숨깁니다. 한 번 하면 앱을 다시 켜도 유지됩니다.

```bash
./scripts/demo.sh panel off
```

4. 브라우저에서 매장 대시보드 `http://localhost:3000/dashboard/`에 시드 계정 `yangjae`로 로그인합니다.

**내비 경로는 띄우지 않습니다.** 에뮬레이터 위치는 판교에 고정이라 내비에 「36분」이 뜹니다. 그러면 앱의 모의 ETA 「6분」과 화면에서 어긋납니다.

## 3. 테이크마다 초기화

```bash
curl -X POST localhost:3000/v1/dev/reset
```

```bash
./scripts/demo.sh reset
```

```bash
./scripts/demo.sh restart
```

- 첫 명령은 서버를 초기화합니다. 진행 주문을 취소하고, 품절·영업 상태를 복구하고, 다음 주문번호를 P-021로 맞춥니다.
- 두 번째 명령은 앱의 모의 ETA를 지웁니다.
- 세 번째 명령은 앱을 홈으로 다시 시작합니다.
- 그다음 Virtual Console에서 기어를 P로 돌리고 대시보드를 새로고침합니다.

## 4. 장면별 조작 (실서버)

| # | 장면 | 조작 | 차량 화면 | 대시보드 | 표기 |
| --- | --- | --- | --- | --- | --- |
| 1 | 주차 중 홈 | 「이 메뉴로 예약」 → 「4,500원 예약 요청」 터치 | V01 → V02 → V03 「매장에서 예약을 확인 중이에요」 | 「매장 확인 중」에 P-021 | 기어 실제 |
| 2 | ETA 공유 | `./scripts/demo.sh eta 6` | 변화 없음 (V03) | 「제조 시작 추천 ○○:○○ (남은 시간)」, 예상 수령·입구 도착·ETA 갱신 시각 | 모의 |
| 3 | 매장 수락 | 대시보드 「수락」 | V04-A 「도착에 맞춰 준비할 예정이에요」 6분 | 「제조 대기」로 이동 | 서버 실제 |
| 4 | 주행 시작 | Virtual Console 기어 D | 주행 화면 (ETA와 단계만) | — | 기어 실제 |
| 5 | 제조 전 정체 | `./scripts/demo.sh delay 4` | 「늦어진 도착에 맞춰 준비할 예정이에요 · 기존 ○○:○○」 | 시작 추천 4분 뒤로, 「추천 변경」 배지와 「제조 시작 추천 4분 늦춤」 알림 | 모의 |
| 6 | 제조 시작 | 대시보드 「제조 시작」 | V04-B 「매장에서 준비하고 있어요」 | 「제조 중」 | 서버 실제 |
| 7 | 제조 후 정체 | `./scripts/demo.sh delay 4` | V05 「이미 준비 중이에요 도착하면 수령해 주세요」 | 「4분 지연」 배지와 「도착 4분 지연」 알림 | 모의 |
| 8 | 준비 완료 | 대시보드 「준비 완료」 | V04-C 「픽업 주문번호 P-021」 | 「준비 완료」 | 서버 실제 |
| 9 | 수령 | 기어 P → 대시보드 「수령 완료」 | V07 「주문을 수령했어요」 | 「수령 완료」 | 결제 목업 |

- 대시보드 대신 터미널로도 같은 조작을 할 수 있습니다: `accept`·`prepare`·`ready`·`pickup`. 영상에는 대시보드 클릭이 연동 증거로 더 낫습니다.
- 「○○:○○」 같은 시각은 촬영 시각으로 계산되어 매번 다릅니다. 「4분 뒤로」가 보이면 됩니다.
- 장면 5·7의 차량 화면 문구는 실서버 E2E 캡처로 확인했습니다.
- 대시보드의 배지·알림은 대시보드 코드로만 확인했습니다 (`pick-me-be/public/index.html` 189-194, 290-299줄). 화면은 확인하지 않았습니다.
- 장면 4의 주행 화면은 실서버로 확인하지 않았습니다.
- 확인하지 않은 것은 리허설 1회차에 확인합니다.

## 5. 가짜 서버로만 보여 줄 수 있는 장면 (넣을 경우)

콘티에는 없습니다. 넣는다면 가짜 서버 빌드로 따로 찍고, 자막에 [가짜 서버]라고 표기합니다.

```bash
./gradlew :app:installDebug
```

| 장면 | 조작 |
| --- | --- |
| 가격 변경 V02-PC | 예약 확인 화면에서 `./scripts/demo.sh price-up` → 「4,500원 예약 요청」 |
| 매장 목록 도착 예상 시간 | 홈 「매장·메뉴 변경」 → 매장 목록(양재 6분·서초 9분) |
