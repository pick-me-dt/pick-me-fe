# 시연영상 촬영 대본 (2026-11-11)

> **실서버 + 실제 내비 + 매장 대시보드로 자동 촬영합니다.** 2차본 결과는 `pickme/video/pickme-demo-v2.mp4`(저장소 밖)입니다.
> 1.2와 5장의 가짜 서버 내용은 참고용입니다.

장면 순서는 2차 기획안 3장 「출근길 아메리카노」와 9장 시연 영상 시나리오를 따릅니다. 앞에는 실제 내비 경로와 매장 추천 장면을 더했습니다.
조작은 모두 녹화 스크립트(`pickme/video/make/record.js`)가 합니다. 터미널 `scripts/demo.sh`, 매장 대시보드 클릭, Virtual Console HTTP를 씁니다. 앱 화면에 시연 컨트롤은 보이지 않습니다(`panel off`).

## 1. 무엇이 실제이고 무엇이 모의·가짜인가

자막의 [실제]·[모의]·[시연 데이터]·[목업] 표기는 이 표를 따릅니다.

### 1.1 실서버로 찍을 때 (결정)

| 구분 | 내용 |
| --- | --- |
| **실제** | 내비 경로와 첫 남은 시간 (Pleos 내비. 「8분 · 1.6km」) |
| **실제** | 주변 매장 검색(거리순), 주문 상태, 제조 시작 추천·예상 수령·지연 계산 (픽미 서버) |
| **실제** | 주문번호 P-021 (서버 초기화 때 맞춤), 대시보드 ↔ 차량 실시간 반영 |
| **실제** | 기어 P/D (Car API. 입력은 Virtual Console HTTP), 주행 중 화면 제한 |
| **모의** | 첫 값 이후의 남은 시간. 실제 시간만큼 줄어드는 값입니다. 에뮬레이터 차량이 움직이지 않아 내비 화면의 시간은 그대로입니다(게이트 G3) |
| **모의** | 정체(도착 지연). 터미널 `delay 4`로 넣습니다. 내비에는 나오지 않습니다 |
| **시연 데이터** | 매장 위치. 에뮬레이터 위치(판교 37.4127, 127.0947) 북쪽 0.8·2.5·5km로 옮긴 값입니다 (`POST /v1/dev/stores/relocate`). 실제 양재 위치가 아닙니다 |
| **서버 목업** | 결제. 예약 때 승인, 수령 때 확정하는 목업이며 실제 결제는 없습니다 (`pick-me-be/README.md` 102줄) |
| **서버 목업** | 매장 POS·DT 연동. 목업 DT 어댑터가 받습니다(외부 주문번호 `MOCK-…`) |
| **서버에 없음** | 가격 변경(V02-PC), 매장 목록의 도착 예상 시간(거리만 있음), 메뉴 옵션(Regular), 브랜드 이름 |

| **가짜** | 품절·가격 변경·접수 종료 (`sold-out`·`price-up`·`closed`) |
| **가짜** | 매장 목록(양재 6분·서초 9분), 메뉴 옵션 Regular, 브랜드 「픽미 커피」. 모두 Figma 예시 값입니다 (`SampleData.kt`) |

| **모의** | ETA (1.1과 같음) |

## 2. 촬영 준비 (한 번만)

1. 백엔드를 켭니다 (`pick-me-be` 폴더).

```bash
docker compose up --build -d --wait
```

2. 앱을 실서버 주소로 설치합니다.

```bash
./gradlew :app:installDebug -Ppickme.serverUrl=http://10.0.2.2:3000
```

3. Virtual Console을 연결합니다. 녹화 스크립트가 콘솔 페이지를 열어 기어 입력을 켭니다(페이지가 한 번 열려야 HTTP 기어 입력이 받아들여집니다).

```bash
~/Library/Android/sdk/platform-tools/adb forward tcp:8088 tcp:8088
```

4. 에뮬레이터 화면을 **「픽미(왼쪽 세로) | 내비(오른쪽)」**로 나눕니다. adb로 재현한 순서입니다(기기 좌표 2560×1440).
   1. 하단 독의 픽미 아이콘을 눌러 픽미를 엽니다.
   2. 앱 영역 오른쪽 끝 「⋮」 손잡이를 왼쪽으로 끕니다 (`input swipe 2546 720 1700 720 800`). 픽미가 왼쪽 840×1210 칸으로 갑니다.
   3. 하단 독의 내비 아이콘을 오른쪽 칸으로 끌어 놓습니다 (`input draganddrop 1154 1370 2120 700 1500`).
   4. 독 편집 창이 열리면 「완료」를 누르고, 앱 서랍은 격자 아이콘으로 닫습니다.
   - 분할은 앱을 다시 시작(`demo.sh restart`)해도 유지됩니다.

## 3. 촬영

`pickme/video/make` 폴더에서 차례로 실행합니다. 자세한 내용은 `pickme/video/README.md`에 있습니다.

```bash
node record.js
```

```bash
node cards.js
```

```bash
node compose.js pickme-demo-v3.mp4
```

녹화 스크립트는 테이크마다 아래를 먼저 합니다.
- 기어를 P로 둡니다.
- 서버를 초기화합니다(`/v1/dev/reset`). 진행 주문을 취소하고, 매장 위치·품절·영업 상태를 복구하고, 다음 주문번호를 P-021로 맞춥니다.
- 매장을 에뮬레이터 근처로 옮깁니다(`/v1/dev/stores/relocate`).
- 앱 기기의 등록 메뉴를 지웁니다. 로컬 서버에서 이 기기로 로그인해 `DELETE /v1/me/favorites/:id`를 부릅니다. 그래서 「등록 내역 없음」에서 시작합니다.
- 내비가 안내 중이면 「안내 종료」를 누릅니다.
- `demo.sh reset`, `panel off`, `restart`를 실행합니다.

- 시각은 촬영 시각으로 계산되어 매번 다릅니다.

## 6. 지난 판과 다른 점

- **1차본** (`pickme-demo-v1.mp4`):
  - 내비를 띄우지 않았습니다.
  - ETA를 `eta 6`으로 넣었습니다.
  - 등록된 평소 메뉴에서 바로 시작했습니다.
- **2차본** (`pickme-demo-v2.mp4`):
  - 화면을 분할해 실제 내비를 함께 띄웠습니다.
  - 매장을 에뮬레이터 근처로 옮겨, 내비 경로와 첫 남은 시간을 실제 값으로 썼습니다.
  - 매장 추천과 메뉴 등록 장면을 더했습니다.
  - 이를 위해 `navi-route`가 좌표를 받도록 바꿨습니다(`demo/DemoCommands.kt`).
