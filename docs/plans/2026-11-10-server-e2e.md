# 실서버 전체 흐름 테스트 (2026-11-10)

차량 앱(Pleos 에뮬레이터), 백엔드(`pick-me-be` `d43e2d2`, 로컬 Docker), 매장 대시보드를 함께 띄워 예약부터 수령·취소까지 확인한 결과입니다. 백엔드는 1차 기획 기준이라 2차 기획과 다른 부분은 아래 3장에 사실만 적었습니다.

## 1. 띄우는 법

**백엔드** (`pick-me-be` 폴더, Docker Desktop 필요)

```bash
docker compose up --build -d --wait
```

- 상태 확인: `http://localhost:3000/v1/health`
- 매장 대시보드: `http://localhost:3000/dashboard/` (`yangjae` / `pickme1234`)

**에뮬레이터**: 실행 방법은 [에뮬레이터 게이트 결과](2026-11-10-emulator-gates.md) 1장을 따릅니다.

**앱**: 서버 주소를 빌드 옵션으로 넘깁니다. 주소를 빼면 앱 안의 가짜 서버를 씁니다.

```bash
./gradlew :app:installDebug -Ppickme.serverUrl=http://10.0.2.2:3000
```

**시연 컨트롤**: 실서버 모드에서는 묶음이 「시작 / 서버 / 이동」으로 바뀝니다.
- 「다음 단계」: 개발 API `/v1/dev/orders/:id/advance`로 주문을 한 단계 넘깁니다. 예약 직후에 쓰면 「매장에 전송」이 됩니다.
- 「서버 초기화」: `/v1/dev/reset`을 부릅니다.
- 매장 쪽 조작(제조 시작·준비 완료·수령)은 대시보드에서 합니다.

## 2. 확인한 흐름

모두 에뮬레이터 화면과 서버 DB로 확인했습니다.

| 단계 | 앱 | 서버 |
| --- | --- | --- |
| 로그인 | 설치마다 만든 기기 ID와 등록한 차량번호로 `POST /v1/auth/device` | 새 사용자·차량 생성 (`12가3456`) |
| 실시간 연결 | `/ws/vehicle` 연결 (`PickmeRealtime: 연결됨`) | — |
| 등록 내역 없음 | 자주 주문 메뉴가 비어 V01-E 표시 | `GET /v1/me/favorites` → `[]` |
| 경로 확인 | 내비 안내가 없으면 V01-R, 「내비게이션 열기」로 내비가 앞으로 옴 | — |
| 매장 검색 | 내비 현재 위치(37.4127, 127.0947) 기준. 판교 2.5km · 정자 5.2km · 양재 8.3km | `POST /v1/stores/search` |
| 메뉴 선택·등록 | 양재점 메뉴 7개 중 아이스 아메리카노 선택 → 홈에 표시 | `favorites`에 저장 (양재점, 메뉴 206) |
| 예약 확인 | 서버 견적 4,500원 | `POST /v1/orders/quote` |
| 예약 요청 | V03 매장 확인 중 | 주문 `RESERVED`, `SCREEN`, Idempotency 키 저장 |
| ETA 전송 | 첫 값은 내비 남은 시간 1200초, 이후 30초마다 모의 감소 | `telemetry` 3건 (1200→1140초, 위치·속도 포함) |
| 매장 전송 | 시연 컨트롤 「다음 단계」 → 실시간 이벤트로 V04-A 제조 대기, 「20분 · 19:55 도착 예정」, 주문 MOCK-CDB5BE39 | `SENT`, 대시보드에 주문 표시(남은 시간이 실시간으로 줄어듦) |
| 제조 시작 | 대시보드 버튼 → V04-B 제조 중 | `PREPARING` |
| 준비 완료 | V04-C 준비 완료 | `READY` |
| 수령 완료 | V07 수령 완료 「수령 완료 19:36」 | `PICKED_UP`, 시각 기록 |
| 취소 | 주문 상세 → 취소 요청 → V06-D 취소 완료 | `CANCELLED`, 사유 `USER` |

**확인하지 못한 것**
- 응답 지연(V03-T), 연결·ETA 오류(V04-E), 제조 전·후 지연(V05)
- 대기열 알림, 앱 재시작 시 진행 주문 복귀(V00-RE)

## 3. 2차 기획과 다른 서버 동작 (테스트에서 관찰)

| # | 관찰한 사실 | 앱에서 한 일 |
| --- | --- | --- |
| 1 | 직원 수락이 없다. 예약 주문(`RESERVED`)은 대시보드에 보이지 않고, 기본 대기 2대일 때는 ETA가 0이 돼야 매장에 전송된다 (`src/timing/estimators.ts:46-48`) | 시연 컨트롤 「다음 단계」(개발 API)로 전송 |
| 2 | 개발 API로 전송하면 전송 시점 ETA가 0으로 기록돼, 바로 「정체로 도착이 20분 늦어져 매장에 알렸어요」 지연 알림이 온다 | 없음 (이벤트를 받으면 주문을 다시 조회만 함) |
| 3 | 취소 요청이 즉시 취소로 끝난다(사유 `USER`). 취소 확인 중·취소 거절 단계가 없다 | 앱은 바로 V06-D로 가고 「매장에서 취소를 승인했어요」가 표시되는데, 실제 흐름과 맞지 않는 문구다 |
| 4 | 주문번호가 `MOCK-XXXXXXXX` 형식이다 (2차 기획 예시 `P-021`) | 준비 완료 화면에서 긴 번호는 한 줄 안에서 글자를 줄임 |
| 5 | 차량용 주문 응답에 입구 도착 예정·예상 수령·시작 추천·ETA 수신 시각이 없다 | 앱이 보낸 ETA로 2차 기획 식을 계산 (입구 이후 2분은 앱 기본값, 준비 시간은 서버 `estPrepSec` 90초) |
| 6 | 텔레메트리에 위도·경도·속도가 필수다. 출처는 서버가 모두 `NAVI`로 기록해 모의 ETA와 구분되지 않는다 | 내비 현재 위치와 속도(권한 없으면 0)를 함께 보냄 |
| 7 | 매장 검색 응답에 도착 예상 시간이 없고 거리만 있다. 기본 반경은 5km다 | 매장 버튼에 거리 표시(「픽미 DT 양재점 · 8.3km」), 반경 15km로 요청 |
| 8 | 매장 이름이 「픽미 DT 양재점」 형식이고 브랜드 이름이 응답에 없다 (Figma: 「픽미 커피 · 양재 DT점」) | 매장 이름만 표시 |
| 9 | 메뉴 옵션(Regular)이 비어 있다 | 옵션 표시 생략 |
| 10 | 견적에 품절·가격 변경 판단이 없다 | V02-SO·PC는 실서버로 재현 안 됨. 접수 종료(V02-CL)는 확인 안 함 |
| 11 | 매장 취소는 사유 `STORE`이고 거절 사유 문구가 없다 | `STORE`를 예약 거절(V03-R)로 표시 |

## 4. 앱에서 바뀐 점

- **실서버 구현** (`data/remote`)
  - 로그인·자주 주문 메뉴·매장 검색·메뉴·견적·예약·텔레메트리·취소·조회를 연결했습니다.
  - 실시간 이벤트는 「주문이 바뀌었다」는 신호로만 쓰고, 받으면 서버에서 주문을 다시 조회합니다.
- **시작 조회 취소 버그 수정**: 실서버처럼 응답이 늦으면, 시작 조회가 화면 효과와 함께 취소되면서 「앱 실행 실패」로 표시됐습니다. 가짜 서버에서는 응답이 즉시 와서 드러나지 않았습니다.
- **메뉴 넘기기**: 메뉴가 3개보다 많으면 「다른 메뉴 보기」로 다음 3개를 보여 줍니다(Figma에 없음).
- **권한**: 「내비게이션 열기」에 `pleos.car.permission.NAVI_CUSTOM_MAP` 권한이 필요해 추가했습니다.
